Signal Radar - Estado v0

Objetivo

Detectar señales combinadas entre:

* Capitol Trades (PTR)
* SEC Form 4 (insiders)
* USASpending (contratos federales)
* SAM.gov Contract Opportunities
* Congress.gov
* Federal Register
* LDA.gov
* SEC EDGAR adicional
* FEC
* Grants.gov

Manteniendo una arquitectura simple:

Fuente
→ CSV
→ Google Sheets
→ signals
→ cluster_signals
→ correlation_signals
→ priority_signals
→ review_queue
→ telegram_alert_log
→ Telegram

Google Sheets es la fuente de verdad.

⸻

Arquitectura interna

collectors/
→ CSV

loaders/
→ raw Google Sheets

radar/
→ utilidades compartidas de Sheets, fechas, filas, IDs y deduplicación

→ validaciones locales y contra Google Sheets

→ punto único de ejecución del radar derivado completo

→ envío de alertas Telegram deduplicadas desde review_queue

→ punto único de validación local sin escribir en Google Sheets

tests/fixtures/
→ CSV mínimos y determinísticos para validación reproducible sin credenciales ni internet

config/scoring.json
→ pesos configurables y auditables para score, score_band y score_reason

El workflow .github/workflows/local_validation.yml ejecuta validación local con fixtures en cada push y pull request.

El workflow .github/workflows/daily_radar.yml ejecuta ingesta diaria controlada, rebuild del radar y alertas Telegram. También puede lanzarse manualmente desde GitHub Actions. Requiere los secretos:

GOOGLE_CREDENTIALS_JSON
GOOGLE_SHEETS_ID
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID

El workflow escribe los secretos de Google en credentials.json y .env dentro del runner, ejecuta collectors, loaders, scripts/rebuild_radar.py y scripts/send_telegram_alerts.py, y no commitea CSV generados.

Las fuentes externas pueden fallar de forma transitoria. Capitol Trades puede devolver HTTP 429 cuando se ejecuta desde GitHub Actions, y SEC o USASpending pueden estar lentas o no disponibles. En ese caso el workflow registra un warning, omite solo el loader de la fuente fallida en esa ejecución y reconstruye el radar usando las raw sheets existentes.

Fase 10 - Conflictos de interés en el Congreso (2026-10-22)

Diagnóstico previo:

* El workflow diario fallaba desde el 2026-07-05 en "Validate raw data quality"; al bloquear, nunca se reconstruía el radar ni se enviaban alertas.
* Capitol Trades fallaba a diario desde GitHub Actions (bloqueo/429), dejando el radar sin operaciones de políticos.
* GitHub desactivó el workflow "Daily radar" el 2026-09-04 por inactividad.

Cambios:

* Nueva fuente oficial: collectors/collect_congress_ptr.py (House Clerk + Senate eFD) -> raw_congress_ptr.
* Enriquecimiento con comités (unitedstates/congress-legislators) y sector del ticker (lista curada + SIC SEC).
* config/conflict_sectors.json: comités -> sectores, definición de sectores y scoring.
* scripts/send_conflict_alerts.py: hojas conflict_trades y ptr_manual_review + alertas Telegram deduplicadas.
* Nuevo signal_type PTR_BUY_CONFLICT integrado en clusters, correlaciones y scoring.
* Validación de calidad y métricas pasan a ser informativas (continue-on-error) y no bloquean el radar.
* Capitol Trades se retira del workflow diario.

Pendiente / limitaciones:

* Senate eFD no se pudo probar desde fuera de EE. UU. (bloqueo geográfico); se valida en la primera ejecución en GitHub Actions.
* Las declaraciones escaneadas (en papel) se listan en ptr_manual_review pero no se leen (sin OCR).
